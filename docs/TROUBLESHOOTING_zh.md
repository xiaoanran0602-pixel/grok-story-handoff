# 故障排查

## 软件找不到模型

确认本地 OpenAI-compatible 服务已经启动，且 Base URL 正确。

默认地址：

```text
http://127.0.0.1:1234/v1
```

如果自动识别失败，可以手动填写模型名。

## `n_keep >= n_ctx` 或上下文长度错误

这通常表示提示词超过了模型当前加载的上下文窗口。

可以尝试：

- 降低 `canon_part_chars`。
- 降低 `old_recent_chars`、`new_head_chars`、`new_tail_chars`。
- 在模型服务里提高 Context Length，并重新加载模型。
- 换更大上下文窗口的模型。

## 模型输出为空

常见原因是模型把输出预算花在隐藏推理上，或者输出 token 太少。

可以尝试：

- 增加 `max_tokens`。
- 降低 chunk 大小，让提示词更短。
- 换稳定的非 thinking instruct 模型。
- 不要把上下文窗口塞得太满。

## 生成的设定太薄

长篇故事很难一次总结完整。可以使用重建或带检查点的流程，让软件分段整理。

也可以尝试：

- 换更稳定听指令的模型。
- 硬件允许时稍微提高 chunk 大小。
- 先重建 story bible，再重新生成 handoff。

## Windows 日志乱码

GUI 会尽量强制 UTF-8。若仍然乱码：

- 检查 Windows 语言和区域设置。
- 从源码运行时尽量使用支持 UTF-8 的终端。
- 测试时先使用简单英文路径。

## Windows 阻止打包版运行

独立开发者未签名软件可能触发 Windows 提醒。

请只从官方 GitHub Releases 页面下载，或者选择从源码运行。

## 软件没有发现 `.mhtml`

检查：

- 文件是否放在你选择的故事目录里。
- 后缀是否是 `.mhtml` 或 `.mht`。
- 浏览器是否完整保存了页面。
- 故事目录是否为空。

## 长任务中途失败

软件会故意写入中间文件。删除前先检查 `debug/` 和 `runs/`。很多情况下可以降低 chunk 后重跑，而不用完全从头开始。
