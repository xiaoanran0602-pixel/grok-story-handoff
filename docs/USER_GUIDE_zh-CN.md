# 中文使用指南

Grok Story Handoff 用来帮助你把长篇 Grok 创作从一个窗口延续到下一个窗口。

## 开始前准备

你需要：

- 一个故事一个专用目录。
- 已保存的 Grok `.mhtml` / `.mht` 对话文件。
- 如果要本地运行 AI 清洗与整理，需要一个 OpenAI-compatible 本地模型服务。

推荐默认模型服务地址：

```text
http://127.0.0.1:1234/v1
```

## 第 1 步：创建故事目录

例如：

```text
D:\Stories\MyNovel
```

同一个故事的所有 Grok 窗口都放在这个目录里。不同故事不要混在同一个目录。

## 第 2 步：保存 Grok 窗口

打开你想继续的 Grok 对话，把完整页面保存成单文件网页归档，如果浏览器支持，会得到类似文件：

```text
story-window-001.mhtml
```

把它放进故事目录。

## 第 3 步：打开软件

运行 Windows 打包版，或者从源码运行：

```powershell
python grok_handoff_gui.py
```

然后选择你的故事目录。

## 第 4 步：选择操作

### 追加新 Grok 窗口

最常用。适合你又写完一个 Grok 窗口，想把它追加到同一个故事项目里。

### 从头重建故事项目

适合之前整理错了，或者想基于保存的 `.mhtml` 重新整理。这个操作可能覆盖已有的 `master/` 和 `handoff/`。

### 只重新生成交接包

适合 `master/` 已经正确，只想刷新下一窗口交接提示词。

## 第 5 步：在新 Grok 窗口继续写

运行结束后打开：

```text
handoff/03_下个窗口直接复制这个.md
```

把全文复制进新的 Grok 窗口，然后继续写。

## 好习惯

- 一个故事一个目录。
- 文件名用 `window-001.mhtml`、`window-002.mhtml` 这种清晰格式。
- 在确认输出没问题前，保留原始 `.mhtml`。
- 不要公开上传原始故事目录。
- 重建前先备份重要故事项目。

## 软件可能生成什么

| 文件夹 | 含义 |
| --- | --- |
| `runs/` | 每个窗口的处理结果。 |
| `master/` | 长期故事正史与设定状态。 |
| `handoff/` | 给下一个 Grok 窗口使用的交接文件。 |
| `debug/` | 长任务中间检查点文件。 |
| `mhtml_archive/` | 可选的已处理 `.mhtml` 存放位置。 |

## 本地模型建议

- 先用中等 chunk 参数，不要一开始就拉太大。
- 如果模型输出为空，换非 thinking 的 instruct 模型，或增加输出 token。
- 如果提示超过上下文窗口，降低 chunk 大小，或提高模型 Context Length。
- 长篇整理更需要稳定听指令的模型，不一定需要最强推理模型。
